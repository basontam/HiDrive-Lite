# Importing a media library

The importer accepts user-owned workbooks from an external directory. It
normalizes provider aliases, groups links by media identity and edition, and
produces a plaintext build bundle. The application encrypts link URLs and
access codes when the bundle is installed.

The public repository does not contain real workbooks. Use the fictional files
generated by tests or provide your own source directory with the columns
documented by `scripts/import_media_library.py --help`.

Recommended flow:

```bash
.venv/bin/python scripts/import_media_library.py \
  --source-dir /path/to/your/workbooks \
  --output .local-index \
  --report build/library-import-report.json

# Inspect the redacted report, then add --write for the bundle.
.venv/bin/python scripts/import_media_library.py \
  --source-dir /path/to/your/workbooks \
  --output .local-index --write

python app.py --library-install .local-index/library-bundle.sqlite
```

The importer is dry-run by default. Reports contain counts, source hashes and
error classes only; they must not contain a URL, access code, title copied from
a private source, or API key.

The stable identity is the media record. Resource groups represent editions
and technical specifications; resource links represent individual providers.
Thus a 115 link and a Quark link for the same edition appear under one title,
while a different release remains a separate group.
